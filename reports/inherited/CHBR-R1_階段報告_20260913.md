## 1. 這個階段做了什麼

### 1.1 先確認了「為什麼非重跑不可」

原始結果有四個**彼此獨立**的缺陷，任何一個都足以讓數字不可用：

| # | 缺陷 | 證據 |
|---|---|---|
| 1 | **資料洩漏**：`prompt最佳化.py` 拿 test set 的 222 筆子集當 Optuna 目標函數 | 程式碼第 17–21 行；已用 `random_state=42` 逐筆重現那 222 筆 |
| 2 | **逐筆預測從未存檔** | 全專案無 npz／無 `檢查用.csv`／無任何預測輸出 → McNemar、bootstrap CI 在數學上無法補算 |
| 3 | **標籤解析器順序偏誤** | `for label in ['Normal',…]: if label.lower() in result.lower()` → `"This is not Normal; it is Depression"` 判成 **Normal** |
| 4 | **Table VIII 的「最佳化 prompt」等於基準 prompt** | 正規化後 Table VIII ≡ `test.py` 的 prompt ≡ 候選模板 #0；且 122 個模板全是同一句指令的措辭改寫（0/122 含 persona、0/122 含 CoT、0/122 含 few-shot） |

缺陷 4 的延伸發現：論文寫「300 prompt variations」，程式碼實際只有 **122** 個候選；
真正勝出的模板只 `print` 到 console、`optuna.create_study()` 未設 `storage=`，**已永久遺失**。

### 1.2 採用「靠剔除而非重建」的修法

不重建資料集、不重建索引、不重新生成擴增資料 —— 把有問題的樣本從評估集剔除：

```
舊 test                2,222
  − TPE 選擇集           222   （追認為 validation set）
  − 逐字汙染             134   （原文在向量庫中，條目還附著 true_label）
  − 近似重複               2   （cosine ≥ 0.95）
= 乾淨候選池           1,882
→ 各類下採樣           1,700   （425 × 4，維持與原設計相同的類別平衡）
```

三個集合（train / val222 / test_clean）互斥，且 `test_clean ∩ train = 0`，已由驗收斷言確認。

相較原方案（去重重建 + 重選 prompt），這個作法把 LLM 呼叫從約 21,600 次壓到約 16,000 次，
GPU 時間從 7–9 小時壓到約 6.7 小時（一個晚上），且**更好答辯** —— 回覆可以直接寫
「我們識別出 222 筆曾用於 prompt 選擇、134 筆與檢索語料逐字重複，全數排除後在剩餘未接觸樣本上重新評估」。

### 1.5 三個實測發現

**(a) 汙染幾乎全是逐字重複，改寫沒有製造新的洩漏路徑**

| 語料 | ≥0.90 | ≥0.95 | 最大相似度 |
|---|---|---|---|
| 未擴增（8,886 筆） | 3 | 2 | 0.9910 |
| 擴增（26,658 筆） | 3 | 2 | 0.9910 |

擴增語料**沒有增加任何一筆**近似重複 —— 這是對 `R3C64` 很乾淨的答案。

**(b) 擴增資料是生成樣板，不是語意多樣性**

17,772 筆改寫文本中：

| 指標 | 比例 |
|---|---|
| 以 `"Here is a rewritten version…"` 開頭 | 66.0% |
| 可剝除的樣板前綴 | 65.7% |
| 原始文本含自身類別詞 | 57.9% |
| 剝除前綴後內文仍含自身類別詞 | 32.7% |
| 內文含**他類**類別詞（標籤噪音） | 13.4% |
| 通過品質過濾 | 10,444（58.8%） |

典型條目長這樣：

```
"Here is a rewritten version of the text:\n\nThere's going to be a karate
 tournament next week. true_label is Normal"
```

向量編碼到的是指令跟隨語而非文本語意 —— 這是擴增只帶來 +0.0009 準確率的直接解釋。

**(c) 一個 8 秒訓練完的 TF-IDF 模型贏過論文的最佳 LLM 設定**

| 系統 | Accuracy | Macro-F1 | 訓練 | 推論（1,700 筆） |
|---|---|---|---|---|
| **TF-IDF + LogReg** | **0.8776** | 0.8771 | **7.8 秒** CPU | 0.3 秒 |
| MiniLM + LogReg | 0.8641 | 0.8637 | 125.9 秒 | 24.7 秒 |
| 論文最佳 LLM 設定（舊數字） | 0.8249 | 0.8293 | 無需訓練 | 數小時 GPU |

而且 0.8249 是在**受汙染的測試集**上、用**有偏誤的解析器**、且 prompt 在測試集上選出來的，
乾淨重跑後只會更低。baseline 這邊完全沒調參，是偏保守的設定。

補充證據：文本本身有很強的字面線索 —— Depression 39.1% 含 `depress*`、
Anxiety 56.9% 含 `anxi*`、Bipolar 57.4% 含 `bipolar`/`manic`，Normal 僅 0.5%。
任務有相當比例是關鍵詞偵測，這也反過來支持 `R3C58`（建議別稱為 sentiment analysis）。
