### 1.8 top-k 的選擇

- 論文採用的規則：在 val（1,000 筆）上掃描 k ∈ {1, 3, 5}，**只看最佳化 prompt 的 C4、C5**，兩組共用一個 k。兩組都是 k = 1 的 macro-F1 最高（C4 0.7914、C5 0.7961），因此 k = 1。數字見 §3。
- k = 5 的 test 結果當敏感度分析（§5.1）。
- **決策經過（內部紀錄，論文要怎麼揭露由作者決定）**：
  1. 2026-10-05：依當時預先定好的規則（四組 RAG 條件的 val macro-F1 平均）選出 k = 5（`TOPK_VAL_AUGV2/selected_k.json`），隨後在 test 上跑 k = 5 主結果，並另跑 k = 1 當敏感度（`MAIN_EVAL_AUGV2_K1/manifest.json` 的 `top_k_source` 記為 `test_sensitivity_not_selected`）。
  2. 2026-10-11：#30 改採「只看 C4、C5」的規則，論文改用 k = 1。當時 k = 1 與 k = 5 的 test 結果都已知（#30 的表格同時列出兩者）。
  - 因此「k 由 val 決定、test 沒有參與選擇」這種寫法與紀錄不符；k = 1 確實是新規則在 val 上的最佳值，但規則本身是在看過 test 結果之後才改的。

### 1.9 標籤解析規則（`src/common.py` 的 `parse_label`）

依序判定：

1. 回應為空 → INVALID（`empty`）
2. 回應中的數字恰好只有一個、且是有效標籤編號 → 接受
3. 出現多個不同的有效編號 → INVALID（`multi_number`）
4. 有數字但沒有任何有效編號 → INVALID（`out_of_range_number`）
5. 其餘情況比對標籤文字（字界、不分大小寫）：**只接受唯一命中** → 接受；多個標籤命中 → INVALID（`multi_label`）
6. 都沒命中時：若有有效編號但混有其他數字 → INVALID（`ambiguous_number`），否則 INVALID（`no_label`）

本實驗的 prompt 要求回覆標籤文字，實際上幾乎都走第 5、6 步。

論文原稿描述的「依固定順序取第一個命中」（first-match）會把 "not Normal; it is Depression" 判成 Normal，因此只當敏感度分析（§4.1）。

### 1.10 統計方法（`src/17_custom_prompt_stats.py`）

- 點估計的 95% CI：10,000 次 bootstrap（seed 42，`numpy.random.default_rng`，每次重抽 1,998 筆，所有條件與配對共用同一組索引，percentile 2.5／97.5）。
- 配對比較：exact McNemar（二項檢定）；Δ 的 CI 用同一組配對 bootstrap。
- 多重比較：Holm–Bonferroni，10 組配對（accuracy 與無效率各自校正）。
- 相對錯誤率下降：(err_前 − err_後) / err_前 × 100。
- 無效回覆的敏感度分析：另算只在有效回覆上的 accuracy 與 macro-F1。

### 10.4 上傳包

`reports/論文交接_v2_k1_上傳包/` 由 `src/29_paper_handoff_bundle.py` 產生，`00_MANIFEST.csv` 記錄每個檔案的來源路徑、大小與 sha256。sha256 是建包當下本機工作目錄的位元組（autocrlf 下的 CSV／JSON 為 CRLF）；上傳包在 git 中設為 `-text`，任何 checkout 都保留相同位元組，但 `runs/` 下的來源檔在其他 checkout 可能換行不同。建議整包放進 Claude Project 的知識庫；如果只在單一對話上傳，先上傳 `00_論文交接_v2_k1.md` 與需要的圖。
