## 5. 主要結果

### 5.1 七個條件

| Case | 設定 | accuracy | macro-F1 | 秒/筆 |
|---|---|---|---|---|
| S0 | 純LLM + 樸素指令 | 0.3918 | 0.3389 | 0.17 |
| **S1** | **純LLM + 最佳化指令** | **0.6414** | **0.6361** | 0.19 |
| S2a | RAG + 樸素指令 | 0.4880 | 0.4309 | 0.66 |
| S2b | RAG + 最佳化指令 | 0.6166 | 0.6050 | 0.65 |
| S3a | 擴增RAG + 樸素指令 | 0.4848 | 0.4332 | 0.63 |
| S3b | 擴增RAG + 最佳化（遷移） | 0.6190 | 0.6075 | 0.67 |
| S4 | 擴增RAG + 最佳化（重搜） | 0.6210 | 0.6097 | 0.63 |

全部 LLM 條件中表現最好的是 **S1——完全不接 RAG 的那一格**。

### 5.2 配對檢定（McNemar + Holm 校正 + paired bootstrap）

| 比較 | 差異 | p_holm | 結論 |
|---|---|---|---|
| S0 → S1 | +24.96pp | <0.001 | **顯著**：prompt 最佳化本身的效果 |
| S0 → S2a | +9.62pp | <0.001 | **顯著**：RAG 本身的效果 |
| S1 → S2b | −2.48pp | 0.064 | 不顯著：好指令之下 RAG 無可測量增益 |
| S2a → S3a | −0.32pp | 1.0 | 不顯著：擴增無效 |
| S2b → S3b | +0.24pp | 1.0 | 不顯著：擴增無效 |
| S3b → S4 | +0.20pp | 1.0 | 不顯著：最佳化結果可跨設定遷移 |
| S0 → S4 | +22.92pp | <0.001 | **顯著**：完整管線相對樸素基準的總增益 |

### 5.3 基準模型（3 seeds，與 LLM 同一份 train/test）

| 模型 | accuracy | 訓練成本 |
|---|---|---|
| **DistilBERT（微調）** | **0.9240 ± 0.0046** | 276 秒（GPU） |
| MiniLM + LogReg | 0.8630 | 19 秒 |
| TF-IDF + LogReg | 0.8558 | **2 秒** |
| 最佳 LLM 條件（S1） | 0.6414 | 無需訓練 |

擴增版全部沒有更好：DistilBERT 0.9140、MiniLM 0.8566、TF-IDF 0.8598。

### 5.4 四個核心結論

1. **prompt 最佳化的效果（+24.96pp）是 RAG（+9.62pp）的 2.6 倍。**
2. **指令寫好之後，RAG 帶不來可測量的增益**（−2.48pp，p=0.064 不顯著），卻讓推論慢 3.5 倍。
3. **資料擴增完全無效**，四個相關比較全部不顯著；對 baseline 亦然。
4. **最佳化 #2 選出與 #1 完全相同的候選**，所以「選型與設定不對齊」這個原研究的隱含問題，實測顯示不影響結果。

最關鍵的對照是 5.3：**DistilBERT 比最佳 LLM 條件高 28pp，訓練只要 2 秒的 TF-IDF 也高 21pp。**

## 6. 執行過程中排除的問題

| 問題 | 根因 | 處置 |
|---|---|---|
| CUDA illegal memory access（多次崩潰） | **MSI Dragon Center 的 GPU 設定**（09-15 22:57 起出現 `nvlddmkm` Event 153），非程式碼問題 | 使用者調回設定後，全 GPU 連續 60 次 + RAG 重負載 30 次零失敗 |
| 崩潰被回報成「執行成功」 | `bash script \| grep` 讓 grep 的 exit 0 掩蓋 python 崩潰 | `run_pipeline.sh` 加 `set -o pipefail` 與 `ERR` trap |
| 「同一腳本被跑兩份」 | **誤判**。`.venv` 以 anaconda 的 python 建立，`python.exe` 只是 launcher shim，兩個程序是常態 | 寫入 README「已知環境行為」 |
| 執行鎖競態 | 「先檢查再寫入」非原子操作 | 改用 `O_CREAT\|O_EXCL` 原子建檔（實測 3 並發正確擋下） |
| 擴增每筆兩版完全相同 | `temperature=0.7` 但 seed 固定 | 每個變體使用不同 seed |
| 擴增過度丟棄含類別詞的樣本 | 原設計丟棄所有「含」類別詞者，但原文本身提到診斷是真實病患語言 | 改為只丟棄「改寫引入」的，保留率 50% → 75.9% |
| Windows Update 強制重啟中斷長跑 | 系統排程 | 中斷續跑機制保住全部已完成資料 |
